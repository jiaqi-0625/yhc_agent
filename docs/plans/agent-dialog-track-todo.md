## 状态规则

| 状态 | 含义 |
|---|---|
| `待开始` | 依赖未满足或尚未领取 |
| `进行中` | 负责人当前正在处理；同一负责人原则上只保留一项 |
| `部分实现` | 已有可验证实现，但尚未满足全部完成标准或仍缺上游依赖 |
| `已实现待集成` | 已在当前分支提交并验证，尚未合并到 `main` |
| `阻塞` | 无法继续，必须填写阻塞原因和解除条件 |
| `待评审` | 本地实现和检查已完成，等待复核或推送 `main` |
| `已完成` | 提交已进入 `origin/main`，检查和验收结果已记录 |

## 实时维护要求

1. 开始工作前先同步 `main` 与 `origin/main`，再更新页首的“当前任务、当前状态、最近更新、最新提交”。
2. 将领取任务的状态改为 `进行中`，集成目标固定为 `main`。
3. 相关检查通过后创建任务范围清晰的提交，以非强制快进方式推送 `origin/main`，并记录功能提交；Agent 行为变化不能只记录在提示词中。只有用户明确要求时才创建功能分支或 PR。
4. 发生阻塞时当天改为 `阻塞`，写清所缺的 Schema、API、产品决定或测试环境。
5. 只有提交已进入 `origin/main`、会话/权限检查通过并完成该任务适用的浏览器联调后才能标记 `已完成`。
6. 对 `TaskContext`、`AgentActionCard` 或可执行工具提出变更时，先与工作区负责人评审，再修改共享契约。
7. 每个工作日结束前刷新一次本页状态，并在更新记录中写明对工作区的影响。

## 代码所有权

对话区负责人主要维护：

- `packages/agent` 中任务级 Agent、会话、系统提示词、流式事件和工具装配；
- Agent 专用的共享消息、计划和操作卡片 Schema；
- `apps/api` 中 Agent 会话、恢复、取消和流式端点；
- `apps/web` 中右侧 Agent 面板、时间线、上下文提示和操作卡片交互；
- Agent 会话隔离、脱敏、审计和工具边界测试。

共享热点：

- `packages/schemas/src/index.ts`：不单方面改变工作区领域对象；通过 WS-005 共同冻结契约。
- `packages/domain`：Agent 不直接添加状态转换；需要新命令时由工作区负责人实现并评审。
- `apps/api/src/server.ts`：优先抽取 Agent 路由，避免与工作区 API 同文件冲突。
- `apps/web/public/app.js`、`app.css`、`index.html`：优先把 Agent 面板迁移到独立模块和样式边界。
- 生产 Agent 不注册 shell、文件系统、SQL、任意 HTTP、浏览器或人工批准工具。
