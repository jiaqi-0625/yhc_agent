## 状态规则

| 状态 | 含义 |
|---|---|
| `待开始` | 依赖未满足或尚未领取 |
| `进行中` | 负责人当前正在处理；同一负责人原则上只保留一项 |
| `阻塞` | 无法继续，必须填写阻塞原因和解除条件 |
| `待评审` | 本地实现和检查已完成，等待复核或推送 `main` |
| `已完成` | 提交已进入 `origin/main`，检查和验收结果已记录 |

## 实时维护要求

1. 开始工作前先同步 `main` 与 `origin/main`，再更新页首的“当前任务、当前状态、最近更新、最新提交”。
2. 将领取任务的状态改为 `进行中`，集成目标固定为 `main`。
3. 相关检查通过后创建任务范围清晰的提交，以非强制快进方式推送 `origin/main`，并在任务备注中记录功能提交；只有用户明确要求时才创建功能分支或 PR。
4. 发生阻塞时当天改为 `阻塞`，写清依赖人、所需决定和解除条件。
5. 只有提交已进入 `origin/main`、相关检查通过并完成该任务适用的自动化或浏览器验收后才能标记 `已完成`。
6. 修改共享 Schema、工作流状态或 API 契约时，同时通知对话区负责人并更新两份清单的依赖项。
7. 每个工作日结束前刷新一次本页状态；没有进展也要确认阻塞说明仍然有效。

## 代码所有权

工作区负责人主要维护：

- `packages/schemas` 中品牌、车型、项目、任务、资产、版本和命令契约；
- `packages/domain` 中工作流、权限、revision、负责人、并发和预算规则；
- `packages/tools` 中资产、视频和自动剪辑领域端口及 Mock 适配器；
- `apps/api` 中工作区、管理中心、项目、任务和资产 API；
- `apps/web` 的应用壳、项目库、管理中心、创建向导和中间工作区。

共享热点：

- `packages/schemas/src/index.ts`：由工作区负责人维护最终结构；对话区通过评审提出字段需求。
- `apps/api/src/server.ts`：优先拆分路由后再并行修改，避免双方长期编辑同一文件。
- `apps/web/public/app.js`、`app.css`、`index.html`：先完成模块边界拆分；拆分前由工作区负责人协调合并顺序。
- `AGENTS.md` 和产品规格：任何改变业务边界的提交都需要双方评审。
