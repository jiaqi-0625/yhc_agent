# ADR-002：私有媒体对象存储与短期访问地址

- 状态：已决定，WS-207 实施中
- 日期：2026-08-20
- 决策人：产品负责人、工作区负责人

## 背景

视频任务聚合已经能持久化阶段版本、人工确认、回退、失效和内容哈希，但真实视频字节不适合写入 PostgreSQL，也不能依赖生成供应商提供的临时下载地址。供应商 URL 可能过期、撤销或改变权限，永久公开 URL 也无法满足租户隔离。

## 决策

1. 视频和后续媒体文件写入服务端控制的私有对象存储；PostgreSQL 不保存视频二进制。
2. PostgreSQL 保存不可变媒体产物记录，包括租户、项目、任务、阶段、版本、媒体属性、字节 SHA-256、对象存储定位符和创建幂等信息。
3. 业务聚合继续只保存 `artifactId`、schema 版本和内容元数据哈希；对象存储定位符不进入 `VideoTask` 聚合。
4. 浏览器只能用认证后的媒体访问 API 按 `artifactId` 请求短期签名 URL。签名 URL 不写入数据库、日志、Agent transcript、提示词或工具结果。
5. Bucket 保持私有；对象键由服务端构造并采用不可覆盖语义。生产环境优先使用工作负载身份，不把长期访问密钥写入仓库或普通配置文件。
6. 对象存储通过 API 基础设施端口隔离。首个适配器采用 S3-compatible 协议，但业务 Schema、领域状态和 Agent 不依赖具体云厂商。
7. 生产 Agent 不注册通用上传、对象存储、任意 URL 或文件系统工具。真实视频生成仍须经过任务负责人、revision、人工动作、账号运行锁、成本预估和预算结算。

## 访问流程

```text
VideoTask / StageArtifactVersion
  -> artifactId
  -> PostgreSQL media_artifacts（租户与对象定位符）
  -> API 重新校验 SessionScope、项目与任务权限
  -> 对象存储生成短期 GET URL
  -> 浏览器播放或下载
```

签名 URL 是短期 bearer 凭据。退出登录后，已经签发的 URL 仍可能在剩余 TTL 内有效，因此首期 TTL 上限保持在 15 分钟，并由 Bucket/IAM 策略限制访问范围。

## 不变式

- 客户端不能提交 tenant、bucket、对象键、永久 URL 或云凭据。
- 跨租户、跨项目、跨任务的 `artifactId` 不得触发签名调用，并统一按不可见处理。
- 媒体字节 SHA-256 与阶段内容元数据哈希是两个不同字段，不能互换。
- 已被确认版本引用的媒体记录保持追加式不可变；回退和失效不删除历史对象。
- 对象上传或复制完成后必须由服务端核验大小、媒体类型和 SHA-256，只有核验通过的记录可以签发访问地址或参与真实阶段确认。

## 后续未决项

云厂商、区域、Bucket 生命周期、版本保留、跨区域灾备、CDN、HLS 分片清单和未引用对象回收策略仍需在真实视频生成纵切前完成容量与成本验证。这些选择不得改变本 ADR 的业务引用和授权边界。
